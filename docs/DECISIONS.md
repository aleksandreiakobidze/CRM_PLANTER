# გადაწყვეტილებები

ეს ფაილი აფიქსირებს რუტინულ ტექნიკურ არჩევანს. ბიზნესპირობები, რომლებიც სპეციფიკაციაში უკვე შეთანხმებულია (მოვლის 10%, ინკლუზიური გაქირავების დღეები, ექსკურსიის 13:00–16:00), აქ არ იცვლება.

## D-001 სტეკი და ბაზა

რეპოზიტორია ცარიელი იყო. არჩეულია Next.js 16.4.2 (App Router, TypeScript strict), PostgreSQL და Prisma ORM 7.10.1.

Prisma 8 2026-10-16 მდგომარეობით release candidate-ია (`8.0.0-rc`) და `db.transaction()`-ს isolation level არ გადასცემს. ნაშთის დადასტურებას `SELECT FOR UPDATE` და serialization retry სჭირდება, ამიტომ დარჩა სტაბილური Prisma 7. კლიენტი არის `prisma-client` გენერატორი `@prisma/adapter-pg`-ით. კონფიგურაციაა `prisma7.config.ts`.

SQLite არ გამოიყენება. გაქირავების გადაფარვა PostgreSQL-ის `btree_gist` exclusion constraint-ია.

## D-002 სესია

better-auth 1.7.11 სესიას ბაზაში ინახავს და revocation-საც იძლევა, მაგრამ საკუთარ user/session სქემას ფლობს. სპეციფიკაცია მოითხოვს Organization, Membership, Role, Permission, Session და Invitation მოდელებს organization_id საზღვრით და როლების ცალკე permissions-ით.

ამიტომ სესია ჩვენია: `@node-rs/argon2` (argon2id), cookie-ში მხოლოდ შემთხვევითი ტოკენი, ბაზაში SHA-256 hash, ყოველ მოთხოვნაზე `revokedAt` და `user.active` მოწმდება. თანამშრომლის გათიშვა ყველა აქტიურ სესიას აუქმებს. Auth.js Credentials არ ავირჩიეთ, რადგან ნაგულისხმევად JWT-ია და გათიშვამდე ვადა არ სრულდება.

პაროლი, ტოკენი და cookie hash audit-ში არ იწერება.

## D-003 ფული და დრო

გამოთვლა `decimal.js`-ით, half-up. ერთეულის ფასი `numeric(18,4)`, დოკუმენტის თანხა `numeric(18,2)`. ბრაუზერის total არ გამოიყენება.

მომენტი `timestamptz` UTC-შია. კალენდარული დღე `date`. „დღეს“ ითვლება `Asia/Tbilisi`-ით `src/server/time.ts`-ში. თარიღის ველს UTC კონვერტაცია დღეს არ უცვლის.

## D-004 მარაგი

ნაშთი არის `stock_balances` (on_hand, reserved) პლუს უცვლელი `stock_movements`. უარყოფითი ნაშთი check constraint-ით იკრძალება. შეთავაზება ნაშთს არ ეხება. შეკვეთის დადასტურება რეზერვავს. მიწოდება ერთხელ ჩამოწერს. ინვოისი მარაგს არ ჩამოწერს. posting key უნიკალურია.

თვითღირებულება ამ ეტაპზე მოძრავი საშუალოა ვარიანტის ჭრილში: opening და შემდგომი მიღება საშუალოს ითვლის, გაყიდვა COGS snapshot-ს ინახავს მოძრაობაზე.

## D-005 PDF

გატარებული ინვოისი ინახავს seller/buyer/lines/totals snapshot-ს. PDF იბეჭდება მხოლოდ snapshot-იდან Playwright Chromium-ით, ჩაშენებული Noto Sans Georgian-ით. RS-ზე რეგისტრაცია არ სრულდება და PDF-ზე ეს პირდაპირ წერია.

## D-006 გარე ინტეგრაცია

Email, SMS, WhatsApp, გადახდის გეითვეი, ბანკი, ERP და RS არიან `not_configured`. Outbox იწერება commit-ის შემდეგ. Worker demo adapter-ს არ აგზავნის რეალურ შეტყობინებას და სტატუსად ტოვებს `not_configured`.

## D-007 ლოკალური ბაზა Docker-ის გარეშე

ამ სამუშაო მანქანაზე Docker არ არის. `docker-compose.yml` მაინც არის Hostinger VPS-ისთვის. ლოკალური გაშვება და ტესტები იყენებს `embedded-postgres`-ს (`npm run db:up`). Production seed და demo პაროლი production-ში იბლოკება.

## D-008 მიგრაციები

სრულ ERD-შია ყველა მომავალი მოდელი. ცხრილები იქმნება მხოლოდ იმ ეტაპზე, რომელსაც კოდი იყენებს. ეტაპები 3–5 (შესყიდვა, სათბურის პარტია, პორტალი, რეალური ინტეგრაცია, AI) ცხრილებს ჯერ არ ქმნის.

## D-009 ფასის პრიორიტეტი

შეთავაზების ხაზზე ფასი ასე ირჩევა: კლიენტის ინდივიდუალური ფასი → რაოდენობრივი ფასი → აქტიური ფასების სია (B2B, საბითუმო, საცალო) → ვარიანტის საცალო ფასი. არჩეული ფასი ხაზზე snapshot-ია. კატალოგის შემდეგი ცვლილება ძველ ხაზს, ინვოისს და მოვლის ბაზას არ ცვლის.

## D-010 დღგ

ორგანიზაციის `taxMode` ნაგულისხმევად `unset`-ია. ეს არ ნიშნავს 0%-იან შეღავათს და არც RS სტატუსს. გადასახადი დაითვლება მხოლოდ მას შემდეგ, რაც უფლებამოსილი მომხმარებელი რეჟიმს ჩართავს (`inclusive`, `exclusive`, `exempt` ან `zero_rate` ცალ-ცალკე).
